# 셀 간 메시지의 동적 양자화: 상황에 따라 VQ 비트 수를 바꿔 왜곡과 성능 손실을 줄이기

- 상태: **아이디어 정리 초안** (paper3 E2–E3에서 전제 조건을 측정한 뒤 진행 여부 결정)
- 작성일: 2026-11-12
- 관련 문서: `docs/paper3_5g_multicell_plan.md`, `paper/main.tex` (paper1), 이전 연구 QH-CTDE 원고

## 1. 아이디어

CTDE 스케줄러에서 각 셀(AP)은 실행 시점에 자기 관측만 본다. 이웃 셀의 정보를 보내면 협조가 좋아지지만,
보내는 양(비트)은 백홀 부담이 된다. 지금까지는 **정보량을 고정값**으로 놓고 비교했다.

| 연구 | 정보 수준 |
|---|---|
| QH-CTDE | VQ 코드북 크기 고정 ($b = 4, 5, 6$ 비트), CA-DSM 게이트로 양자화 정보 사용 여부만 켜고 끔 |
| paper1 | 0-bit (MAPPO) 대 ∞-bit (Central PPO) |
| paper3 계획 | 정보 수준 $b \in \{0, \infty\}$ |

제안은 **비트 수를 상황에 따라 바꾸는 것**이다. 정보가 쓸모 있는 순간에는 많은 비트로 정밀하게(왜곡 작게) 보내고,
쓸모없는 순간에는 적게 보내거나 보내지 않는다. 같은 평균 비트로 고정 비트보다 성능 손실을 더 줄이는 것이 목표다.

## 2. 왜 지금 이 아이디어가 맞는가

1. **정보 가치는 평균적으로 작다.** paper1에서 정보 손실 $\Delta_{\text{I}}$는 고정 토폴로지에서 −2 ~ +9점,
   무작위 토폴로지에서 1–3점이었다. 항상 많은 비트를 보내는 것은 낭비다.
2. **하지만 협조 이득은 조건부로 열린다.** paper1에서는 제공 부하가 Co-TDMA 용량을 넘을 때($\rho > 1$)만,
   paper3 파일럿(E1)에서도 부하가 클수록 협조 이득이 커졌다. 정보가 필요한 순간이 따로 있다는 뜻이다.
3. **셀룰러에는 정보 가치를 바꾸는 시간 변동 요인이 많다.** CQI 지연과 UE 속도가 크면 지역 관측이 낡아지고,
   이웃 셀 정보의 가치가 달라질 수 있다.
4. **이전 연구에서도 "많을수록 좋다"가 아니었다.** QH-CTDE의 코드북 크기 실험(T6, C4)에서 차단 횟수는
   $b$가 커질수록 줄었지만(1.345 → 0.893 → 0.613 /step, $b = 4, 5, 6$), ARF를 붙인 처리량은 $b = 5$가 가장 컸다
   (747 → 945 → 901). 고정된 하나의 $b$가 모든 상황에 최적이 아니라는 직접 근거다.
   (출처: QH-CTDE 원고 `tab:codebook_size`, 2026-10-22 5시드 결과. 원고에 넣을 때 수치 재확인.)

## 3. 정식화

셀 $c$가 슬롯 $t$에 보내는 메시지와 왜곡:

$$
m_c(t) = Q_{b_c(t)}\bigl(f_\psi(o_c(t))\bigr), \qquad
D(b) = \mathbb{E}\bigl\|f_\psi(o) - Q_b(f_\psi(o))\bigr\|^2,
$$

- $f_\psi$: 관측을 메시지 특징으로 바꾸는 인코더, $Q_b$: $b$비트 양자화기, $b_c(t) \in \mathcal{L} = \{0, 2, 4, 6, 8\}$.
- $b = 0$이면 메시지를 보내지 않는다(MAPPO와 같음).

목적함수(비트 비용 $\mu$를 둔 라그랑주 형태):

$$
\max_{\pi, \beta}\ \mathbb{E}\Bigl[\sum_t V(t)\Bigr] - \mu\, \mathbb{E}\Bigl[\sum_t \sum_c b_c(t)\Bigr],
\qquad b_c(t) = \beta\bigl(z_c(t)\bigr),
$$

- $V(t)$: paper3의 슬롯 효용(처리량 또는 PF), $\beta$: 비트 수를 고르는 정책.
- $z_c(t)$: 비트 결정에 쓰는 지역 신호. 예: 백로그로 추정한 부하, CQI 보고의 나이와 변화율, 간섭 추정치.
- $\mu$를 바꾸면 "평균 비트 대 성능" 곡선 전체를 얻는다.

### 3.1 중첩 코드북 (구현의 핵심)

비트 수마다 별도 인코더를 두면 슬롯마다 바꿀 수 없다. **잔차 벡터 양자화(residual VQ)**를 쓰면
$b$비트 메시지가 더 정밀한 메시지의 앞부분이 된다.

- 2비트 단계 4개를 쌓으면 $b = 2, 4, 6, 8$이 모두 같은 인코더에서 나온다.
- 수신 측은 받은 단계까지만 더해 복원한다. 비트 수를 바꿔도 네트워크는 하나다.
- 현재 `vector_quantizer.py`는 단일 코드북이므로 잔차 단계를 추가해야 한다.

### 3.2 비트 정책 $\beta$의 후보

| 이름 | 방식 | 근거 |
|---|---|---|
| F-$b$ | 고정 $b$ (기존 방식) | 기준 |
| G-2 | 0 또는 $b_{\max}$ 두 단계, 지역 신호의 문턱값 | QH-CTDE의 CA-DSM 게이트(`dsm_gate.py`, 고정 문턱 `gamma_margin`)를 그대로 확장 |
| G-L | 여러 단계 문턱값 | 부하 추정치 구간마다 $b$를 정함 |
| L | 학습된 비트 선택기 | actor에 비트 선택 헤드를 추가하고 보상에서 $\mu b$를 뺌. 중앙 critic은 학습에만 쓰이므로 CTDE 구조 유지 |

## 4. oracle 틀에서의 평가

이 아이디어는 paper1·paper3의 손실 분해와 바로 연결된다.

| 기준 | 역할 |
|---|---|
| 0-bit (MAPPO) | 하한 |
| ∞-bit (Central PPO) | 정보로 회복할 수 있는 상한. 그 차이가 $\Delta_{\text{I}}$ |
| F-$b$ | 고정 비트, 같은 평균 비트의 비교 대상 |
| G-2, G-L, L | 제안 |
| 정확 oracle | 전체 상한 |

- **핵심 그림:** 가로축 평균 비트(셀당 슬롯당), 세로축 oracle 대비 효용. 고정 비트 곡선과 동적 비트 곡선을 겹쳐 그린다.
  동적 곡선이 위에 있으면 같은 비트로 더 좋은 것이다.
- **회복률:** $(\rho_{\text{dyn}} - \rho_{0}) / \Delta_{\text{I}}$. 같은 평균 비트에서 고정 $b$의 회복률과 비교한다.
- **왜곡과 성능의 관계:** $D(b)$와 효용 손실을 함께 보고, 왜곡이 큰 순간이 성능 손실이 큰 순간과 겹치는지 확인한다.
- **백홀 부담 환산:** $b$비트 × 클러스터 셀 수 × 슬롯 1,000개/초. 예: $b = 6$, $C = 3$이면 18 kb/s.

## 5. 전제 조건과 진행 판단 (가장 먼저 할 것)

동적 양자화가 의미 있으려면 **정보 가치 $\Delta_{\text{I}}$가 조건에 따라 크게 달라야** 한다.
평균도 작고 변화도 작으면, 비트를 아무리 잘 배분해도 얻을 것이 없다.

- **주의:** paper3 E1 파일럿(배치 20, 시드 1, 부대역 1, $C = 3$, 처리량 목적)에서 전체 재사용이 oracle의 96–99%였다.
  이 설정에서는 협조 자체의 여지가 1–4%뿐이므로 정보의 여지는 더 작다.
- **측정:** paper3 E2(고부하 손실 분해)와 E3(CQI 지연 × UE 속도)에서 $\Delta_{\text{I}}$를 조건별로 기록한다.
  추가로 PF 목적, $C = 7$, 부대역 4개에서도 본다.
- **판단 기준(안):**

| 측정 결과 | 결정 |
|---|---|
| 어떤 조건에서도 $\Delta_{\text{I}} < 3$점 | 동적 양자화는 paper3의 논의(discussion) 한 문단으로만 다룸 |
| 조건 사이 $\Delta_{\text{I}}$ 차이가 5점 이상 | paper3의 한 절로 추가하거나 별도 논문(paper4)의 주제로 진행 |
| 그 사이 | G-2(문턱 게이트)만 구현해 작은 실험으로 확인 |

## 6. 구현 계획 (진행이 결정되면)

1. **메시지 경로를 paper3 시뮬레이터에 추가.** 지금 학습자는 0-bit(MAPPO)와 ∞-bit(Central PPO) 두 가지다.
   그 사이에 "$b$비트 MAPPO"를 만든다. 각 에이전트는 자기 관측과, 다른 셀이 보낸 양자화 메시지를 받는다.
2. **잔차 VQ 인코더.** `vector_quantizer.py`를 단계형으로 확장하고, 코드북 초기화는 `codebook_init.py`를 재사용한다.
3. **비트 정책.** G-2는 `dsm_gate.py`의 고정 문턱 구조를 여러 단계로 일반화한다. L은 actor에 헤드를 하나 추가한다.
4. **실험 스크립트.** $\mu$ 스윕과 고정 $b$ 스윕을 같은 배치·시드에서 돌려 곡선을 만든다.
5. **테스트.** $b = 0$에서 MAPPO와 같은 결과, $b$가 커질수록 $D(b)$ 감소, 잔차 단계의 앞부분 복원이 낮은 $b$와 같음.
