- 작성일: 2026-10-29
- 브랜치: `feat/paper2-mobility-roaming`

## 1. 목적과 연구 질문

이전 논문은 연결(association)을 고정한 채 정확 oracle 대비 손실을 분해했다.
후속 논문은 STA가 이동하면서 생기는 **잘못 연결된 구간(mis-association window)**과 **AP 간 플래핑**을 다루고,
MAPC가 이 손실을 얼마나 줄이는지와 그 결과 로밍 파라미터의 최적점이 어떻게 바뀌는지 보인다.

| 번호 | 질문 | 가설 |
|---|---|---|
| RQ1 | 닫힌형 식(`paper2` IV절)이 시뮬레이션과 맞는가? | 결정적 채널에서 $T_{\text{MA}}$는 오차 5% 이내, 플래핑 확률은 $n_{\text{TTT}}=1$에서 상한으로 성립 |
| RQ2 | 로밍 손실은 얼마이며, 그중 잘못 연결된 구간 몫은 얼마인가? | 표준 보행 속도에서 잘못 연결된 구간 몫이 핸드오버 중단 몫보다 크다 |
| RQ3 | MAPC가 잘못 연결된 구간 손실을 얼마나 회복하는가? | 정확 oracle은 상당 부분을 회복하고, Co-TDMA는 고부하에서만 회복한다 |
| RQ4 | MAPC가 있으면 최적 히스테리시스가 커지고 플래핑이 줄어드는가? | 최적 $\Delta_{\text{hys}}$가 커지고, 같은 처리량에서 핸드오버 횟수가 줄어든다 |
| RQ5 | 재연결 없는 서빙 AP 전환(802.11bn 끊김 없는 로밍)은 이득이 얼마인가? | 전환 비용이 작으면 이상적 연결 상한에 가깝다 |
| RQ6 | 학습 스케줄러(MAPPO, Central PPO)는 연결 변화 하에서 oracle 대비 얼마나 잃는가? | 연결 변경 직후 구간에서 손실이 커진다 |

## 2. 설계 원칙

1. **표준 정합성**: IEEE 802.11 TG 평가 방법론은 STA를 고정하거나 직선 등속 이동만 쓰고,
   Gauss–Markov 같은 확률적 이동 모델은 정의하지 않는다(2026-10-29 기준 확인 범위).
   따라서 **주 시나리오는 직선 등속 이동**으로 하고, **Gauss–Markov는 강건성 평가(E6)**로 둔다.
   `paper2/main.tex` III-A의 이동 모델 서술도 이에 맞게 고친다(9절).
2. **이전 논문과의 비교 가능성**: 경로손실, MCS 표, 슬롯 길이 1 ms, 큐 모델, 정확 oracle, 무작위 토폴로지는
   그대로 재사용한다. 새 기능은 설정 키(`mobility.enabled`, `roaming.enabled`)로 켜고, 기본값은 꺼진 상태로
   두어 이전 논문 결과가 바뀌지 않게 한다.
3. **분석이 먼저**: 실험 범위는 IV절 닫힌형 식으로 먼저 거른다. 의미 없는 조합(로밍이 아예 일어나지 않는 조합 등)은
   실행하지 않는다(3.2절).
4. **가정 표시**: 표준 문서로 확인하지 못한 수치(핸드오버 지연, 속도 범위)는 "가정"으로 표시하고,
   IEEE Mentor 원문으로 확인한 뒤 확정한다(10절).

## 3. 시나리오

### 3.1 시나리오 정의

| ID | 이름 | 배치 | 이동 | 역할 |
|---|---|---|---|---|
| S1 | 두 AP 직선 횡단 | AP 2개(간격 $L$), AP당 고정 STA 2개(배경 부하) + 이동 STA 1개 | AP1 → AP2 직선 등속, 시작 $x_0 = 0.25L$, 끝 $x_1 = L$ | 닫힌형 검증, 주 결과 |
| S2 | 경계 체류 | S1과 같음 | 경계($x = L/2$) 근처에서 왕복(진폭 $A$) 또는 정지 | 플래핑 스트레스 |
| S3 | 무작위 토폴로지 보행 | 이전 논문 무작위 토폴로지 2단계 20개 ($N = 3$–6) | STA 일부(25%)가 무작위 방향 직선 등속, 영역 경계에서 반사 | 일반화 |
| S3-GM | S3 + Gauss–Markov | S3과 같음 | Gauss–Markov ($\beta$, $\bar{v}$, $\sigma_v$) | 강건성 (E6) |

- S1의 배경 STA는 이전 논문 토폴로지처럼 각 AP 서빙 거리 비율 $r/d \in \{0.2, 0.4\}$ 위치에 고정한다.
  배경 STA가 있어야 잘못 연결된 구간에서 간섭과 스케줄링 선택이 생기고, MAPC 이득이 드러난다.
- S2의 왕복은 결정적 궤적이므로 플래핑 원인이 측정 편차뿐인지, 위치 변화까지 포함하는지를 분리할 수 있다.

### 3.2 분석으로 본 파라미터 범위 (S1, $P_{\text{tx}} = 15$ dBm, 경로손실 지수 3)

로밍 임계값 조건이 성립하는 거리 $x_{\text{roam}} = 10^{(P_{\text{tx}} - 46.67 - R_{\text{roam}})/30}$:

| $R_{\text{roam}}$ | $x_{\text{roam}}$ | $L = 15$ m ($L/2 = 7.5$) | $L = 20$ m ($L/2 = 10$) | $L = 30$ m ($L/2 = 15$) |
|---|---|---|---|---|
| −60 dBm | 8.8 m | 임계값 지배 (1.3 m) | **히스테리시스 지배** | 히스테리시스 지배 |
| −65 dBm | 12.9 m | 임계값 지배 (5.4 m) | 임계값 지배 (2.9 m) | 히스테리시스 지배 |
| −70 dBm | 18.9 m | **로밍 없음** ($x_{\text{roam}} > L$) | 임계값 지배 (8.9 m) | 임계값 지배 (3.9 m) |
| −75 dBm | 27.8 m | 로밍 없음 | **로밍 없음** | 임계값 지배 (12.8 m) |

히스테리시스만으로 정해지는 거리 $x_\Delta - L/2 = (L/2)\tanh(\Delta_{\text{hys}}\ln 10/60)$ ($L = 20$ m):
$\Delta_{\text{hys}} = 1, 3, 6, 10$ dB에서 각각 0.38, 1.15, 2.26, 3.66 m.

표의 "지배" 구분과 괄호 안 거리(잘못 연결된 구간의 공간 길이 $x_{\text{roam}} - L/2$)는 $\Delta_{\text{hys}} = 3$ dB 기준이다.
$\Delta_{\text{hys}}$가 커지면 경계가 옮겨 간다(예: $L = 20$ m, $R_{\text{roam}} = -65$ dBm은 $\Delta_{\text{hys}} = 10$ dB에서 히스테리시스 지배).

결론:

- $R_{\text{roam}} = -70$ dBm, $L = 20$ m에서는 $\Delta_{\text{hys}}$가 결과에 영향을 주지 않는다
  (잘못 연결된 구간 8.9 m가 임계값으로 정해진다). **히스테리시스 트레이드오프(RQ4)는 히스테리시스 지배 조합에서만 본다.**
- "로밍 없음" 조합은 sticky client 사례로 E2에 1개만 넣고, 나머지 스윕에서는 뺀다.
- 에피소드 길이: S1에서 $L = 20$ m, $v = 1$ m/s면 15 m 이동 = 15초 = 15,000 슬롯이다.
  이전 논문 에피소드(200 슬롯)의 75배이므로 학습자는 구간을 잘라 학습한다(6절).

## 5. 비교 스케줄러와 연결 정책

연결 정책(누가 어느 AP에 붙는가)과 스케줄러(붙은 상태에서 누가 전송하는가)를 분리해 조합한다.

| ID | 연결 | 스케줄러 | 역할 |
|---|---|---|---|
| P0 | 로밍 규칙 | 비협조 (AP별 greedy + ARF) | MAPC 없는 기준 |
| P1 | 로밍 규칙 | Co-TDMA | 단순 협조 |
| P2 | 로밍 규칙 | 연결 반영 정확 per-slot oracle | 로밍 하 협조 상한 |
| P3 | 이상적 연결 (매 슬롯 최대 RSSI, 중단 없음) | 정확 per-slot oracle | 전체 상한 |
| P4 | 스케줄러가 서빙 AP 선택, 전환 비용 $c_{\text{sw}}$ | 유한 기간 oracle (기간 $H$) | 끊김 없는 로밍 (RQ5) |
| P5 | 로밍 규칙 | MAPPO (0-bit) | 학습자, 지역 관측 |
| P6 | 로밍 규칙 | Central PPO (∞-bit) | 학습자, 전체 관측 |

- 로밍 손실 = P3 − P2 (협조가 있을 때), P3 − P0 (협조가 없을 때).
- MAPC 회복 비율 $\eta = 1 - (P3 - P2)_{\text{MA}} / (P3 - P0)_{\text{MA}}$, 잘못 연결된 구간 슬롯만 집계.
- P4는 이동 STA 수가 적은 S1/S2에서만 돌린다. 상태 수가 $N^{M_{\text{mov}}}$이므로 S3에서는 계산이 커진다.

### 학습자 처리 (E5, E6)

- 에피소드를 1,000 슬롯 구간으로 잘라 학습한다. 구간 끝은 종료가 아니라 잘림(truncation)으로 처리해
  가치 함수로 부트스트랩한다. 각 구간의 시작 위치는 궤적 위에서 무작위로 뽑아 경계 근처 구간이 충분히 나오게 한다.
- 평가는 잘라내지 않은 전체 궤적으로 한다.
- 관측에 이웃 AP의 필터링된 RSSI, 연결 상태, 중단 여부를 추가하고, 도달 불가 STA는 행동 마스킹한다.

## 8. 통계 처리와 계산량

- 시드: 경로·측정 편차·트래픽·페이딩 RNG를 분리하고, 같은 시드에서 스케줄러끼리 짝지어 비교한다.
- 신뢰구간: `experiments/analyze_paired_bootstrap.py`로 쌍별 부트스트랩 95% 신뢰구간을 낸다.
- 계산량(추정, 파일럿에서 확인):
  - 기준 정책: 이전 논문 1단계 스윕(25,200 슬롯 × 정책 6개)이 4코어 약 24초 → 슬롯·정책당 약 1 ms 미만.
    S1 횡단 1회(15,000 슬롯) × 스케줄러 4개는 수십 초. E0–E3 전체는 수 시간 안쪽으로 예상한다.
  - 정확 oracle은 $N = 2$(S1)에서 가볍고, $N = 6$(S3)에서는 이전 논문과 같은 비용이다.
  - 유한 기간 oracle(P4): 이동 STA 1개, $N = 2$, $H \le 200$이면 동적 계획법 상태 2개로 가볍다.
  - 학습자: 이전 논문 기준 1,000 에피소드(200 슬롯) 학습이 MAPPO 약 7.5분, Central PPO 약 14분.
    1,000 슬롯 구간이면 같은 에피소드 수에 약 5배. E5 S3 20개 × 부하 2 × 학습자 2 × MCS 2는
    약 1–2일(작업자 4개)로 예상하므로, 이전 논문처럼 두 기계로 나눠 돌린다.

   - 설정 키가 꺼져 있으면 기존 결과와 비트 단위로 같아야 한다.
4. **oracle 확장** `src/training/oracle_policy.py`
   - 매 슬롯 연결 상태에서 $\mathcal{S}_i(t)$를 받아 전수 탐색(P2). P3, P4는 별도 함수.
5. **실험 스크립트** `experiments/roaming_gap.py`
   - `oracle_gap.py`의 작업 단위 JSON 저장과 이어서 실행 구조를 재사용한다.
   - 시나리오 S1–S3를 `configs/roaming_scenarios.yaml`로 정의한다.
6. **테스트**
